## 独立公开采样

脚本：`scripts/probe-sevenm-sina-public.py`，复用独立澳客验证脚本的编码和证据提取工具。两者均无数据库、VIPC 或业务服务调用。运行结果写到新的 `reports/source-probes/sevenm-sina/<UTC运行时间>/`。

```powershell
python scripts/probe-sevenm-sina-public.py --date 2026-11-13 --limit 10
```

本次运行：`reports/source-probes/sevenm-sina/20261113T174234727776Z/report.html`。

- 7M：首页、指定自然日完场页、该页公开加载的日期数组文件均 HTTP 200。取得 72 条长度对齐的比赛/球队/联赛/比分数组，抽取 10 条原始样本。原始记录还包括半场、排名、角球等字段，但存在空值，尚未完成业务语义验收。不能把 `euro` 等开关字段误当成赔率值。本次未取得可确认的多公司完整初即时盘或竞彩盈亏。
- 新浪：从公开赛程抽取 10 场不同 ID 的足球详情链接，均 HTTP 200，但静态响应未识别出有效报价表；其中存在 JavaScript 跳转和动态页面结构，不能把可打开页面当作完整数据可用。
- 两者不是同一批比赛的对照实验：7M 为自然日完场池，新浪为当前未来赛程池，不计算跨站百分比。
- 新浪公开盈亏文章定义为负值盈利、正值亏损，不能与其他来源的盈亏字段直接拼接。文章不是结构化逐场全量 API。
- 没有将新来源接入原始比赛、分析或模型流程。没有启停或重启服务。

## 给供应商的字段验收需求（未发送）

目标：替代现有 VIPC 足球数据功能，不接受只提供比分或泛称“赔率齐全”。请按以下项目逐项回复有/无、对应接口、字段、样本、更新时间、历史范围和月/年报价。

1. 全量足球比赛赛程赛果、状态、主客队、联赛赛季轮次、北京时间与原始时区、半场和常规时间全场比分、竞彩编号，以及来源比赛/球队 ID。
2. 双方近 10/20 场、同主客交锋、未来赛程、赛前积分排名；每场需日期、联赛、主客、半全场比分。避免以赛后状态回填赛前快照。
3. 威廉、Bet365、平博各公司胜平负初盘与即时盘、时间戳；威廉和 Bet365 亚盘/大小球初即时盘、盘口及两侧水位。列出公司 ID 和市场分开的 ID 映射规则、赔率格式、缺盘/封盘约定。平均欧赔需说明公司集合。
4. 中国竞彩胜平负、让球胜平负（含让球数）、比分（全部选项）、总进球（0至7+）、半全场的完整报价；需要开售初赔、当前值、每次变动时间与完整序列，并明确是否真正初赔或首次采样值。
5. 对照 VIPC `tzbl`：三项报价、概率、支持比例、误差、心理误差。说明比例来自真实销售资金、用户投票、保存方案还是推算，不能混用。
6. 对照 VIPC `jyykSpf`：主/平/客支持率、盈亏率 `hy/dy/ay`、冷热 `hlr/dlr/alr`；对照 `jyykRqspf`：让球数、让球胜平负报价/支持率/盈亏率。给出符号、单位、分母、公式、采样范围和来源说明。无法证明与原字段同口径，必须列为不同来源，不能声称无缝替代。
7. 如提供必发：主平客成交量、成交赔率、成交比例、挂买/挂卖价量、变动历史、冷热和盈亏公式，金额币种与去重口径；独立于竞彩保存比例与盈亏交付。
8. 从同一天至少 10 场竞彩赛事提供完整 JSON 样本，含冷门联赛、未开盘/封盘/取消和实际缺失情况。报价需含 API、历史、调用频率、并发、IP限制、存储与展示范围及试用条件。

只有 1—6 项实际样本满足需要且核实数据独立于故障中的 VIPC 后，才能判定可以完整替代。第 7 项为用户额外关注的必发数据，也应单独确认。现有 VIPC 原逻辑、来源标识和历史数据继续保留，不自动切换。
