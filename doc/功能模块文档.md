## 3. 数据爬虫模块

### 3.1 概述
- **位置**: `go_crawler/`
- **语言**: Go
- **数据源**: `vipc.cn` API
- **运行方式**: 独立运行，每次拉取当天数据

### 3.2 数据接口

| # | 接口名称 | URL | 说明 |
|---|---------|-----|------|
| 1 | 比赛列表 | `vipc.cn/i/live/football/date/today/next` | 今日全部比赛 |
| 2 | 历史战绩 | `vipc.cn/i/match/football/{matchId}/history` | 双方交锋记录 |
| 3 | 欧赔数据 | `vipc.cn/i/match/football/{matchId}/odds/euro` | 各公司欧赔 |
| 4 | 盘口数据 | `vipc.cn/i/match/football/{matchId}/odds/pankou` | 亚盘+大小球 |

### 3.3 入库表映射

| 接口 | DB 表 | 备注 |
|------|-------|------|
| 比赛列表 | `moneys` | 比赛基本信息（队名/比分/时间/联赛等） |
| 历史战绩 | `history_moneys` | JSON 存储（交锋/近况/联赛/排名） |
| 欧赔数据 | `odds_moneys` | JSON 存储（全部赔率 + 威廉/Bet365） |
| 盘口数据 | `pankou_moneys` | JSON 存储（亚盘/大小球 + Bet365） |

### 3.4 附加功能
- 自动下载球队 Logo → `public/footballimg/`
- 反爬策略: 随机 IP + User-Agent + 1.5 秒请求间隔
- 数据冲突处理: `ON CONFLICT UPDATE ALL`

## 4. 数据库设计

### 4.1 爬虫数据表

| 表名 | 说明 | 主要字段 |
|------|------|---------|
| `moneys` | 比赛主表 | match_id, date, league, home, guest, scores, logos, status |
| `history_moneys` | 历史战绩 | match_id, league_stat, against, recent, rank, future (JSON) |
| `odds_moneys` | 欧赔数据 | match_id, data(全部), avg_odds, william, bet365 (JSON) |
| `pankou_moneys` | 盘口数据 | match_id, asia_data, dxq_data, bet365 (JSON) |

### 4.2 业务数据表

| 表名 | 说明 | 主要字段 |
|------|------|---------|
| `users` | 用户 | username, nickname, avatar, email, badge, balance |
| `followed_teams` | 关注球队 | user_id, team_id, team_name, team_logo |
| `experts` | 专家 | name, avatar, specialty, accuracy, streak, followers, verified |
| `expert_tips` | 专家预测 | match_id, expert_id, prediction, confidence, analysis |
| `news` | 新闻 | title, summary, content, image_url, category, source, is_hot |
| `transfer_rumors` | 转会传闻 | player_name, from_club, to_club, value, trust_level, status |
| `notifications` | 通知 | user_id, type, title, message, icon, is_read |
| `wallet_transactions` | 交易记录 | user_id, type, amount, description, detail |
| `rewards` | 奖品 | name, description, icon, icon_color, cost, is_active |
| `search_histories` | 搜索历史 | user_id, query |
| `predictions` | 预测记录 | user_id, match_id, prediction, result, odds, amount, payout |
| `leaderboard_entries` | 排行榜 | user_id, username, accuracy, points, rank, period, change |
| `league_standings` | 积分榜 | league, team_name, rank, played, won, drawn, lost, points |
| `top_scorers` | 射手榜 | league, player_name, team_name, goals, assists, rank |

## 6. 可扩展功能建议

以下功能参考市面主流足球预测/体育 App（如 FotMob、SofaScore、365Scores、BetBuddy、Tipster）。

### 6.1 🔐 用户认证 (高优先级)

**当前缺失**: 无登录/注册/JWT 认证机制，所有 API 默认返回 userId=1。

| 功能 | 说明 |
|------|------|
| 注册/登录 | 邮箱+密码、手机号+验证码 |
| JWT Token 认证 | 中间件鉴权，所有用户相关 API 需 Token |
| 第三方登录 | Google/Apple/微信一键登录 |
| 忘记密码 | 邮箱验证码重置 |
| 用户资料编辑 | 修改头像/昵称/邮箱 |

### 6.2 📊 实时数据推送 (高优先级)

| 功能 | 说明 |
|------|------|
| WebSocket 实时比分 | 进球/红牌/中场等事件即时推送 |
| 比赛事件时间线 | 进球/换人/犯规/角球逐分钟记录 |
| 实时赔率变动 | 赔率波动推送 |
| 比赛状态变更 | 开赛/中场/结束通知 |

### 6.3 📈 高级数据分析

| 球队表现趋势图 | 近 N 场得失球/积分趋势 |
| 预期进球 (xG) | 高级统计指标展示 |
| 阵容对比 | 首发阵容可视化对比 |

## 7. 独立平局模型验证（2026-10-20）

入口为管理后台「统计分析 → 平局模型验证」，路由 `/statistics/draw`。默认进入全量历史验证，未来赛程位于次要标签页。复用已有比赛、战绩、赔率、盘口与分析结果，独立记录模型和检验结果。

### 7.1 历史回算、检验与校准

- 汇聚 `money`、`moneys` 和嵌套历史战绩，按比赛标识等规则去重，保留每场比赛的数据来源及限制。现有历史无需等待新增赛前冻结记录即可回算。
- 按比赛时间逐场构造输入：分别统计双方最近 10 场、主队最近 10 个主场和客队最近 10 个客场，以及进失球、平滑平局率、低比分占比和历史基准；只纳入目标比赛之前已经结束的战绩。样本不足按实际数量展示，无有效输入时不使用 33% 兜底。
- 使用攻防参数和比分分布计算平局概率，欧赔先按公司去水后聚合；盘口作为特征，不直接等同预期进球。复用现有 66 个分析信号及已有数值，分别检验基础模型、市场与已有分析数据。
- 模型按时间划分训练、校准、测试三个区间，比例为 60% / 20% / 20%。校准和建议选平阈值仅使用校准区，不使用测试赛果；页面另列独立测试区指标。主流程通过历史样本校准并按条件激活模型，不再以等待 400 场未来冻结样本为前提。
- 数据覆盖不同的探索组可以使用该组自己的历史时间拆分，不能把它的训练内命中当作全局测试成绩。模型对比同时显示该组样本、命中数 / 选平数、命中率、覆盖率、找回率，以及固定共同样本的场数和 Brier；不同分母分别列出。探索模型不因探索命中率高就自动成为未来赛程默认模型。
- 列表保留全部历史比赛，支持日期、联赛、球队、分区、误判和漏选筛选。每场详情可核对近 10 场输入、预期进球、历史基准、市场来源、已有信号及各组分区。手动改变阈值属于探索，查看测试结果后反复调参的成绩不作为独立验证结论。
- 仅结算常规 90 分钟及补时；取消、延期、腰斩和无法确认常规时间比分的加时/点球比赛排除。重建核查曾汇聚 9,476 场，其中 9,362 场可计算、114 场预热或数据不足，测试区 1,873 场；实际数量以最新重建报告为准。

### 7.2 数据时间与归档

原采集器将源站无时区的开赛墙钟存入 DATETIME。独立板块以 `DRAW_SOURCE_TIMEZONE`（默认 `Asia/Shanghai`）解释该字段，再转换为 UTC 做赛前判断；不修改原始时间数据。日期筛选沿用源站北京时间赛程日期，页面时间固定按 `Asia/Shanghai`（北京时间）显示，不受浏览器或服务器时区影响。修改源时区配置后需要重启 API。

`history_moneys`、`odds_moneys`、`pankou_moneys` 的可空 `captured_at` 仅在原始战绩/报价主体成功更新时记录真实采集时间。交易量、排名刷新不更新报价采集时间；无时间的旧报价留空，不能批量补成当前时间。历史回算可展示旧盘口和已有分析的探索对照，但缺少可信赛前采集时间或采集晚于开赛时明确标注，不计作真实赛前成绩。

- `draw_historical_runs`：压缩归档每次历史重建的模型、报告和样本，保留可复核的历史校准过程。
- `draw_feature_snapshots`：保存真实赛前的标准化输入、原始数据、参数、版本和筛选政策。
- `draw_predictions`：每场首次真实赛前预测唯一；刷新和重复生成不覆盖，赛后仅更新赛果及对账信息。真实封存成绩与历史探索回算分别统计。
- `draw_model_runs`：兼容原有冻结样本训练参数和激活记录。旧 `/api/draw/train` 及其至少 400 条有效冻结样本的 Fit 流程继续兼容，不是管理页面的历史校准入口。

## 8. 平局比赛观察（2026-10-21）

- 次数筛选由服务端在全量匹配比赛中执行，再统计总数并分页。某组启用次数条件时，该组必须有有效历史样本；没有记录不当作 0 次平局。列表展示交锋平局数/样本数，展开可核对交锋明细；原两个标签不应用次数条件。

- 页面分别显示读取中、查询失败、条件尚未查询、成功查询零场及总数非零但当前页为空；编辑条件或接口校验失败后，不再以“没有满足条件的比赛”代替尚未获得的查询结果。
- 列出欧赔主/平/客初赔与本地最新赔率，以及亚盘和大小球的初盘、本地最新盘、两侧水位、公司与采集时间。同一市场不拼接不同公司；优先新采集整包对应市场，避免旧拆列掩盖最新数据或空市场。缺失赔率显示暂无。

### 单日读取与性能

原观察接口每次请求都读取全库战绩、欧赔、盘口 JSON，解析并统计后才分页；数据库已有索引也无法加速这种无条件全表读取。原库已核对 `moneys.date` 索引与各附表 `match_id` 唯一索引，单日目标查询可以使用现有日期索引，无需为本次调整新建索引或修改表结构。

读取改为先按单日筛选实际比赛，只为对应比赛读取赔率和盘口需要的字段。全库历史只作为赛前战绩输入，投影必要列。最初使用 30 秒内存缓存复用解析结果和索引，现已改为下述 Redis 持久结果；翻页与修改次数条件不会重复解析历史。观察页「刷新本地数据」传 `refresh=1` 明确重新生成当前日期的本地结果，不触发外部采集、模型重建或源数据库写入。

观察页面另使用专用战绩解析器，仅读取需要的字段，先按有效比赛 ID 去重，再转换比分、时间与球队资料，减少重复 JSON 分配；旧模型共用的解析器不变。保留主表权威覆盖、首次有效副本、源日期时区和赛前完赛边界规则。原始交锋 JSON 到最终交锋统计有完整链路及旧解析器差分测试。

2026-10-21 UTC 实测页面北京时间当天（2026-10-22）的 43 场比赛：运行中旧接口连续三次 HTTP 耗时为 5,367 / 5,133 / 5,055 毫秒，43 条均不提供交锋字段。新代码直接只读原库的首次读取由 2,067 毫秒降至 1,407 毫秒，其中战绩解析由 1,269 毫秒降至 600 毫秒；缓存读取连同 JSON 编码为 1.0–1.8 毫秒。后两项是直接执行读取逻辑的测量，未启动新 HTTP 服务，也不包含浏览器绘制时间。

### Redis 持久计算结果（2026-10-22）

查询改为读取已经生成的整日结果，不再以程序内存中的 30 秒 TTL 决定结果是否存在。使用现有 Docker Redis 的 `127.0.0.1:6379`，不新增服务，不改共享 Redis 的配置或其他应用的键。连接可由 `DRAW_OBSERVATION_REDIS_URL` 配置，默认 `redis://127.0.0.1:6379/0`。本功能键限定为 `peak-ball:draw-observations:v2:<来源数据库身份摘要>:base` 与 `:day:YYYY-MM-DD`，均不设过期时间；来源身份包含 MySQL 实例 UUID 和数据库名，避免混读另一份同名库。

基础结果保存解析后的历史和主表信息；每个日期只保存一份完整比赛明细、常规时间平局集合、两种范围的全库汇总、近 10 场/交锋、原始公司报价及前台分析。今日、历史平局、次数筛选、全部/竞彩、联赛、搜索和分页在该日结果上执行相同筛选，不为每组查询参数重新生成。应用重启可直接从 Redis 读取整日结果；新日期首次生成也可复用 Redis 中的历史基础数据，不必再次读取 28.6 MB 历史 JSON。
